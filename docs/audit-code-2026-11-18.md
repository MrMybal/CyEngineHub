# Audit du code de CyEngineHub

**18 novembre 2026 · 2.0.0-alpha.45 · révision `868c534`.** La compilation Windows Release réussit et les 950 tests .NET passent sur le compte du projet. La priorité est l’intégrité des fichiers lors du placement des packages, de la compression et du nettoyage. Deux autres corrections concernent directement la possibilité de compiler ou de charger un projet Unreal.

## Résultat après correction

Les corrections sont appliquées dans la copie de travail. Un package copié entre volumes est publié avant le nettoyage de sa source. Si ce nettoyage échoue, la destination reste disponible. La compression et Safe Clean vérifient les chemins aux étapes de lecture et de suppression qui les concernent. Les connecteurs publient leur package dans une destination distincte du dossier temporaire.

La création de projets et l’installation des plugins Unreal, l’identification des racines Git, les délais de reprise du script Fab et la fermeture du bureau ont également été corrigés. Pour les reçus d’import Fab, la lecture et l’écriture utilisent désormais une limite de 128 Mio. Une écriture qui dépasserait la limite interrompt l’import et déclenche sa restauration. Les journaux de patch Epic sont incrémentaux, et la reprise reste compatible avec le format précédent.

- Compilation Windows Release réussie avec 0 avertissement et 0 erreur. Les 966 tests .NET, les 29 tests JavaScript et le test de contrat natif CyUI passent.
- Les scénarios Avalonia de fermeture pendant une installation, de suivi d’activité et de galerie Fab passent sur des données de test. Avec 1 000 fichiers, la médiane locale de 20 appels de maintenance à chaud du cache passe de 40 ms à environ 0,06 ms, hors décodage et rendu.
- Les règles Game, Editor et module générées compilent avec les assemblages UnrealBuildTool de neuf versions locales du moteur. Un transfert réel de C: vers D: a été vérifié avec un package fictif, d’abord normalement, puis avec un fichier source verrouillé. Dans les deux cas, le fichier, le manifeste et le répertoire vide ont été retrouvés à destination. La source verrouillée a été conservée.
- Un contrôle Windows exécute la suite .NET sur les demandes de fusion. [Configuration GitHub Actions](../.github/workflows/dotnet-tests.yml)

Les constats et les numéros de ligne qui suivent correspondent à la révision auditée avant correction.

## Intégrité des fichiers

1. **Le déplacement entre volumes peut perdre la seule copie complète d’un package.** Le routeur copie le package vers un répertoire temporaire, supprime récursivement la source, puis renomme la copie. Si la suppression échoue après quelques fichiers, par exemple sur un fichier verrouillé, le traitement d’erreur voit que la source existe encore et efface la copie complète. Finaliser la destination avant de nettoyer la source. Une erreur de nettoyage doit laisser le package publié disponible et signaler les fichiers source restants. Couvrir cette branche par une erreur de suppression simulée à mi-parcours. [Déplacement et traitement d’erreur, lignes 129 à 139](../src/CyEngineHub.Fab/Storage/MarketplaceStorageRouter.cs#L129)

2. **La compression ZIP peut supprimer des fichiers hors du package.** L’inventaire descend récursivement avant de contrôler les attributs des fichiers. Une jonction de répertoire peut ainsi faire entrer des fichiers ordinaires extérieurs dans la liste à supprimer après archivage. Le contrôle des répertoires intervient après cette suppression. À l’inventaire, contrôler chaque répertoire avant d’y descendre. Au nettoyage, garantir que chaque cible appartient toujours au répertoire autorisé. [Inventaire, ligne 265](../src/CyEngineHub.Fab/Packaging/LibraryPackageService.cs#L265) · [Ordre du nettoyage, ligne 395](../src/CyEngineHub.Fab/Packaging/LibraryPackageService.cs#L395)

3. **Safe Clean contrôle la cible finale mais peut traverser une jonction dans un dossier parent.** Le service confirme que le nom complet correspond à un dossier Unreal autorisé. Pour une cible comme `Saved/Logs`, la vérification des attributs du dernier dossier ne garantit pas que le chemin physique reste dans le projet. Résoudre et valider les composants du chemin à la préparation puis au moment de la suppression. Le comportement attendu est un refus avant toute modification si la cible physique sort du projet. [Validation du chemin, ligne 184](../src/CyEngineHub.Storage/Cleanup/StorageCleanupService.cs#L184) · [Contrôle précédant la suppression, ligne 93](../src/CyEngineHub.Storage/Cleanup/StorageCleanupService.cs#L93)

4. **Un import local peut annoncer un succès avec un package déjà supprimé.** Cas reproduit avec la DLL Release et un fichier fictif. Quand la bibliothèque configurée contient le répertoire temporaire `ConnectorImports`, le routeur juge le package déjà en place. L’importeur supprime ensuite ce même répertoire. Au retour, le fichier original existe, mais le chemin du package et celui du manifeste sont introuvables. Donner au package un emplacement définitif distinct avant de rendre la main. Tester l’existence du manifeste après le retour de la méthode avec cette configuration. [Appel du connecteur, ligne 110](../src/CyEngineHub.Desktop/ViewModels/MainWindowViewModel.MarketplaceConnectors.cs#L110) · [Retour anticipé, ligne 104](../src/CyEngineHub.Fab/Storage/MarketplaceStorageRouter.cs#L104) · [Nettoyage final, ligne 141](../src/CyEngineHub.Fab/Packaging/ConnectorLibraryPackageService.cs#L141)

## Compatibilité Unreal

- **Les projets C++ générés pour UE 5.3 ne peuvent pas compiler leurs règles de cible.** Le générateur écrit `BuildSettingsVersion.V5` dans les cibles Game et Editor. Dans les sources d’UnrealBuildTool 5.3 installées, `BuildSettingsVersion` s’arrête à `V4`. Choisir la valeur d’après la version ou les modèles du moteur sélectionné. Un test qui fait compiler les règles générées par UnrealBuildTool couvrirait ce défaut. [Génération des cibles, ligne 529](../src/CyEngineHub.Projects/Creation/ProjectCreationService.cs#L529)
- **L’installation d’un plugin avec sources peut omettre ses DLL tierces indispensables.** Le filtre ignore tout dossier nommé `Binaries` lorsque `HasSource` est vrai. Le modèle `ThirdPartyLibrary` livré avec UE 5.3 déclare pourtant une DLL dans `$(PluginDir)/Binaries/ThirdParty` parmi ses dépendances d’exécution. Préserver les binaires tiers distribués et exclure les sorties de modules effectivement régénérables. Tester un plugin qui contient à la fois ces deux types de fichiers. [Filtre de copie, ligne 357](../src/CyEngineHub.Plugins/Installation/PluginInstallationService.cs#L357)
- **Un remplacement de plugin peut produire un faux doublon dans le catalogue.** L’ancienne version est conservée sous `Plugins/.cyenginehub-backups`, puis la découverte parcourt cette sauvegarde comme un plugin installé. Placer les nouvelles sauvegardes hors des racines de découverte et exclure le dossier historique pour les installations existantes. Vérifier le catalogue après un remplacement suivi d’une actualisation. [Création de la sauvegarde, ligne 186](../src/CyEngineHub.Plugins/Installation/PluginInstallationService.cs#L186) · [Exclusions du scanner, ligne 20](../src/CyEngineHub.Plugins/Discovery/PluginDiscoveryService.cs#L20)

- **Un seul descripteur mal formé peut interrompre la découverte de tous les plugins.** Si le JSON est valide mais que sa racine a une forme inattendue, l’accès à une propriété peut lever une exception que la boucle de découverte ne traite pas. Valider d’abord la forme du document et convertir les erreurs de lecture du candidat en diagnostic individuel. [Lecture de propriété, ligne 200](../src/CyEngineHub.Plugins/Parsing/UpluginDescriptorParser.cs#L200) · [Traitement par candidat, ligne 79](../src/CyEngineHub.Plugins/Discovery/PluginDiscoveryService.cs#L79)

## Autres défauts fonctionnels

- **Quitter pendant une installation peut bloquer le processus.** À la fermeture, le thread d’interface attend synchroniquement la fin du planificateur. Un travail actif peut lui-même attendre un rappel sur ce même thread pour rechercher ou publier un package local. Déclencher l’annulation puis attendre les travaux de façon asynchrone pendant que l’interface peut encore traiter ses rappels. Tester une fermeture avec ce rappel en attente. Ce constat vient du chemin d’exécution. [Arrêt du bureau, ligne 377](../src/CyEngineHub.Desktop/App.axaml.cs#L377) · [Rappel attendu, ligne 9366](../src/CyEngineHub.Desktop/ViewModels/MainWindowViewModel.cs#L9366)
- **Le statut Git peut disparaître pour un moteur ouvert via un chemin court Windows.** Le service compare le texte du chemin fourni avec celui renvoyé par Git. Les noms Windows 8.3 et longs peuvent désigner le même répertoire. Trois tests Git échouent avec un répertoire temporaire en notation courte, puis les 12 tests de la suite passent avec un chemin long. Comparer l’identité effective des deux répertoires tout en conservant le rejet d’un dépôt situé dans le parent du moteur. [Comparaison de racines, ligne 19](../src/CyEngineHub.Git/Analysis/EngineGitStatusService.cs#L19)
- **Un pack déjà téléchargé peut être refusé pour manque d’espace sur le même volume.** La sélection exige à nouveau l’équivalent de la taille du pack en espace libre. Or, sur le même volume dans le cas courant, l’opération suivante renomme seulement le dossier. Calculer séparément les octets supplémentaires à allouer et le quota logique de la bibliothèque. [Sélection, ligne 77](../src/CyEngineHub.Fab/Storage/MarketplaceStorageRouter.cs#L77) · [Renommage, ligne 125](../src/CyEngineHub.Fab/Storage/MarketplaceStorageRouter.cs#L125)
- **Un gros import Fab peut disparaître de l’historique d’annulation.** Le service accepte jusqu’à 100 000 fichiers et écrit un reçu détaillé. Au rechargement, il ignore tout reçu de plus de 8 Mio, taille qu’un import autorisé peut dépasser. Utiliser un format paginé ou borné de manière cohérente et tester la disponibilité de l’annulation après redémarrage. [Écriture du reçu, ligne 781](../src/CyEngineHub.Fab/Import/FabProjectContentImportService.cs#L781) · [Limite à la relecture, ligne 303](../src/CyEngineHub.Fab/Import/FabProjectContentImportService.cs#L303)
- **Le script Fab interprète deux fois un délai de limitation HTTP.** Contrôle hors ligne avec une réponse 429 simulée et un en-tête `Retry-After` de 45 secondes. Le script essaie aussi d’interpréter « 45 » comme une date, puis transmet à la temporisation une durée de plusieurs centaines de milliards de millisecondes. Traiter les secondes et les dates dans deux branches exclusives et vérifier le délai transmis. Le script et ses tests étaient présents localement et non suivis par Git au début de l’audit. [Calcul du délai, ligne 123](../scripts/fab-megascans-library.js#L123)

L’installation d’un package local offre aussi une économie d’E/S simple à estimer. La préparation calcule l’empreinte des fichiers source. L’exécution relit la source pour la vérifier, la relit encore pour la copier, puis vérifie la copie temporaire. Calculer la deuxième empreinte source pendant la copie économiserait une lecture complète du package. Conserver les contrôles de l’inventaire et de la copie avant la publication en destination.

# CyEngineHub 2.0.0-alpha.37

Build local Windows, non publié sur GitHub.

- Les installations Fab/Megascans peuvent avancer en parallèle : jusqu’à quatre
  tâches d’installation, avec deux opérations par disque local et une par partage
  réseau UNC. Les actions générales gardent leur limite existante ; les téléchargements
  gardent leur propre réglage de concurrence. Les ressources communes sont protégées
  entre ces files, notamment les projets déjà utilisés par un build.
- Windows est interrogé en lecture seule pour identifier les disques physiques,
  y compris un volume couvrant plusieurs disques. Si l’information est inaccessible,
  le budget utilise le lecteur/volume. Ce n’est pas une détection SSD/HDD ni une
  promesse de débit. Les dossiers temporaires, les sources et les destinations sont
  inclus dans le budget d’E/S ; un disque commun peut donc limiter le parallélisme.
- Deux écritures dans le même projet/dossier, y compris un sous-dossier, ne démarrent
  pas ensemble. Un pack local peut être partagé entre plusieurs lecteurs, mais pas
  avec une tâche qui le télécharge ou le modifie. Une tâche bloquée ne monopolise
  plus un worker : les tâches indépendantes peuvent passer. Les attentes indiquent
  leur motif, et les conflits conservent l’ordre d’arrivée.
- L’installation recherche maintenant la variante exacte dans le stockage local
  indexé avant d’appeler le client réseau, y compris les packs fournisseur normaux,
  bruts ou ZIP. Les scripts travaillent sur des copies temporaires séparées ; les
  archives originales ne sont ni déplacées, ni recompressées, ni remplacées.
- La sélection initiale préfère une variante locale de la plateforme courante.
  Chaque variante indique si elle est disponible localement. Une autre variante
  explicitement choisie n’est jamais substituée : si elle est absente, un transfert
  peut être nécessaire. Une erreur d’archive locale ne déclenche pas silencieusement
  un nouveau téléchargement.
- Le catalogue local est mis à jour avant de libérer la ressource d’un téléchargement
  d’installation terminé, afin que l’installation suivante réutilise ce pack.
- Plusieurs installations indépendantes peuvent être lancées sans cocher le forçage.
  La case de forçage reste disponible et conserve la méthode et les options choisies.

L’identification Windows suit les API officielles de
[résolution volume/disques](https://learn.microsoft.com/en-us/windows/win32/fileio/basic-and-dynamic-disks)
et [IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS](https://learn.microsoft.com/en-us/windows/win32/api/winioctl/ni-winioctl-ioctl_volume_get_volume_disk_extents).

Validation : tests de l’ordonnanceur et clics d’interface sur deux projets fictifs,
avec import réel d’un pack brut puis ZIP, client réseau configuré pour échouer s’il
était appelé, vérification des originaux et conservation des contrôles du pont éditeur.
Les conversions Unreal restent expérimentales ; le parallélisme ne change pas leur
périmètre de compatibilité.
